# п3.2.3 — что добавлено в код

## Идея

В п3.2.2 процессор запускал каждый отдельный замер АЦП. Теперь АЦП сам выполняет преобразования с частотой 44 100 Гц, складывает результаты в FIFO, а DMA переносит их в массив RAM. Процессор получает только одно прерывание по завершении всего блока.

## Файлы

- `CMakeLists.txt`: добавлена зависимость `hardware_dma` и исходник `logic/block-task/block-task.c`.
- `platform/platform.h`: объявлены функции запуска, проверки готовности и получения блока.
- `platform/platform.c`: добавлены непрерывный режим АЦП, FIFO/DREQ, настройка DMA, массив на 8192 отсчёта и короткий обработчик `DMA_IRQ_1`.
- `logic/block-task/block-task.h/.c`: неблокирующая задача ждёт только флаг готовности на итерациях суперцикла и передаёт данные сохранённому callback.
- `logic/api/api-callbacks.c`: добавлена команда `dma_cap <N>` и расчёт времени, min, max, mean.
- `main.c`: добавлен вызов `block_task_handle()` в суперцикл.
- `check-3-2-3.py`, `.github/workflows/check-3-2-3.yml`: проверка курса и GitHub Actions.

## Самое важное

1. `adc_set_clkdiv()` задаёт частоту измерений.
2. `adc_fifo_setup(true, true, 1, false, false)` включает FIFO и запрос DMA при наличии одного отсчёта.
3. `DREQ_ADC` разрешает перенос, когда FIFO подготовил данные.
4. `DMA_SIZE_16` переносит каждый код в `uint16_t`.
5. `channel_config_set_read_increment(false)` оставляет адрес FIFO неизменным.
6. `channel_config_set_write_increment(true)` продвигает адрес по массиву.
7. `on_block_done()` только отмечает окончание и возвращает АЦП в режим одиночного измерения. Печать и расчёты остаются в обычном коде.
8. `block_task_handle()` не ждёт: если блок ещё не готов, функция сразу возвращается.

## Расчёт ожидаемого времени

Частота `PLATFORM_SAMPLE_RATE_HZ = 44100` Гц. Для `N` отсчётов:

\[
t_{expected}=\frac{N\cdot 1\,000\,000}{44\,100}\text{ мкс}.
\]

Например, `N = 4410` даёт ровно 100 000 мкс (0,1 с).

## Команды проверки

```text
dma_cap 1000
dma_cap 4410
dma_cap 8192
```

Ошибочные аргументы по заданию:

```text
dma_cap 0       -> error: N must be 1..8192
dma_cap 9000    -> error: N must be 1..8192
dma_cap         -> error: usage dma_cap <N>
```
