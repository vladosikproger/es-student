# П3.1.4 — как измерения RP2040 превращаются в таблицу и график

Этот материал следует исходному заданию «п3.1.4 Считывание данных в Python». Здесь не появляется новый датчик или новая физическая цепь: используется прошивка `311-adc`, готовая после п3.1.3. Новая часть — программа на компьютере, которая принимает телеметрический поток, сохраняет данные и визуализирует их.

## 1. Идея занятия: перейти от отдельного ответа к набору данных

В п3.1.1 и п3.1.2 команды `get_voltage` и `get_temp` выполняли измерение по запросу. В п3.1.3 команда `tm_start` включила периодический поток: прибор сам формирует строки вида:

```text
tm: 15349046 0.512 27.1
tm: 15399053 0.602 26.7
tm: 15449053 0.518 26.7
```

В п3.1.4 Python становится регистратором данных (data logger): запускает поток, принимает его, складывает в CSV и строит график.

Общая цепочка:

```text
Физические источники
  ├─ напряжение на GP26
  └─ внутренний температурный диод кристалла RP2040
             ↓
       Аналоговый мультиплексор АЦП
             ↓
      SAR-АЦП: код напряжения
             ↓
   Прошивка формирует строку tm:
             ↓
   USB CDC / виртуальный COM-порт
             ↓
       pySerial в Python
             ↓
      разбор текстовой записи
             ↓
           CSV-файл
             ↓
         matplotlib
             ↓
          PNG-график
```

Физическая измерительная часть находится на Pico. Python не измеряет напряжение и не читает аналоговый сигнал напрямую. Он принимает уже оцифрованные значения, вычисленные прошивкой.

## 2. Что происходит физически на плате

### 2.1. Напряжение на GP26

Внешний сигнал поступает на аналоговый вход GP26 (канал 0 АЦП). Внутренний мультиплексор выбирает канал, схема выборки-хранения фиксирует входное напряжение, а SAR-преобразователь получает 12-разрядный код. В используемой прошивке `platform_voltage_read()` переводит код в приближённое напряжение.

Если GP26 оставлен неподключённым, он является плавающим входом: у него нет жёстко заданного потенциала. На него воздействуют наводки, шумы и паразитные ёмкости, поэтому цифры могут заметно меняться. Такой график показывает поведение плавающего входа, а не измерение стабильного источника.

### 2.2. Температура кристалла

Внутри RP2040 находится температурный датчик, основанный на полупроводниковом диодном переходе. Его напряжение зависит от температуры. Прошивка выбирает канал 4 АЦП, измеряет напряжение и переводит его в температуру по калибровочной аппроксимации из документации RP2040:

```c
T = 27.0f - (U - 0.706f) / 0.001721f;
```

Python получает уже число в градусах Цельсия. Он не выполняет эту физическую калибровку повторно.

### 2.3. Дискретизация и квантование

Измерение не является непрерывным. При периоде 100 мс прибор делает примерно 10 записей в секунду. За 10 секунд получается около 100 записей. При периоде 50 мс — около 20 записей в секунду.

Каждое измерение — отдельный отсчёт. Между отсчётами программа не знает, каким было точное значение сигнала. График лишь соединяет точки линией для удобства просмотра; он не превращает дискретные измерения в непрерывную запись.

АЦП имеет 12-битный код: 4096 возможных кодов от 0 до 4095. При условном диапазоне 3.3 В идеальный шаг равен:

\[
\Delta U = \frac{3.3}{4096} \approx 0.000806\text{ В}=0.806\text{ мВ}.
\]

Внутренний датчик имеет наклон около 1.721 мВ на градус. Поэтому изменение на один идеальный код соответствует примерно:

\[
\Delta T \approx \frac{0.806}{1.721} \approx 0.468 ^\circ\text{C}.
\]

Именно поэтому температура на графике может выглядеть ступенчатой, с изменениями примерно по половине градуса. Это эффект конечного разрешения АЦП и округления вывода, а не обязательно резкое физическое изменение температуры.

Фактическая точность RP2040 хуже идеальной 12-битной модели: на результат влияют шум, нелинейность и опорное напряжение. Поэтому не следует считать каждый младший бит абсолютно точным измерением.

## 3. Почему временная метка берётся с микроконтроллера

Каждая строка `tm:` содержит `time_us` — время измерения по аппаратному таймеру RP2040, в микросекундах.

Почему нельзя просто взять `time.time()` на компьютере в момент получения строки? Между физическим измерением и моментом, когда Python обработает байты, есть задержки: прошивка форматирует строку, USB накапливает/передаёт данные пакетами, драйвер Windows помещает байты в буфер, Python просыпается и читает порт. Эта задержка может немного изменяться.

Следовательно, время приёма на ПК не тождественно моменту измерения. Для оси времени используем `time_us`, созданный прибором в момент телеметрического отсчёта.

В `save_csv()` первая метка вычитается из каждой последующей:

\[
 t_i = \frac{time\_us_i-time\_us_0}{10^6}.
\]

Деление на миллион переводит микросекунды в секунды. Благодаря вычитанию первой метки график начинается с `0.000000` секунд, а не с нескольких миллионов микросекунд после загрузки платы.

## 4. Что такое USB CDC и почему в Windows виден COM-порт

Плата общается с компьютером через USB. Прошивка Pico SDK предоставляет интерфейс USB CDC (Communication Device Class) — виртуальный последовательный порт. Windows показывает его как COM3 или другой номер.

Это не означает, что на плате обязательно задействованы физические UART TX/RX. В данном проекте поток передаётся по USB, но приложения видят привычный интерфейс COM-порта.

Скрипт не жёстко прописывает `COM3`. Он ищет устройство по USB-идентификаторам:

- VID `0x2E8A` — Vendor ID Raspberry Pi;
- PID `0x000A` — Pico SDK CDC UART для RP2040.

Это позволяет автоматически найти плату, даже если Windows назначила ей COM4 или COM7.

## 5. Почему pySerial читает байты, а не готовые строки

USB/COM-порт — поток байтов. Один вызов `read(256)` означает «верни до 256 байтов», а не «верни ровно одну телеметрическую строку». Вызов может получить:

- половину строки;
- одну целую строку;
- несколько строк вместе;
- меньше байтов, чем запрошено, если истёк тайм-аут.

Поэтому скрипт хранит накопительный буфер `received`. Он добавляет туда очередную порцию байтов, а затем выделяет все завершённые строки по символу `\n`. Неполный хвост остаётся в буфере до следующего чтения.

Пример: два чтения могут дать:

```text
Чтение №1: "tm: 1000000 0.512"
Чтение №2: " 27.1\r\ntm: 1100000 0.514 27.1\r\n"
```

После склейки получается полный текст. Только после нахождения `\n` строку безопасно передавать в `parse_record()`.

## 6. Разбор функций программы

### 6.1. `find_board()` — найти плату

```python
for port in list_ports.comports():
    if port.vid == VENDOR_ID and port.pid == PRODUCT_ID:
        return port
return None
```

`list_ports.comports()` перечисляет последовательные порты, которые видит операционная система. У каждого порта есть имя устройства и USB-идентификаторы. Если VID и PID совпали, возвращается этот порт. `None` означает, что подходящая плата не найдена.

### 6.2. `parse_record(line)` — разобрать одну строку

Строка имеет ровно четыре поля, разделённые пробелами:

```text
tm: 15349046 0.512 27.1
```

`split()` делит текст на слова. Проверка `len(parts) != 4` отсеивает строки неправильной структуры, а `parts[0] != "tm:"` — команды, эхо и служебные ответы. Затем `int()` переводит время в целое число, `float()` — напряжение и температуру в числа с плавающей точкой. `ValueError` возникает, если текст нельзя корректно преобразовать. В таком случае функция возвращает `None`.

### 6.3. `collect(device, seconds, period_ms)` — принять поток

```python
with serial.Serial(device, timeout=0.1) as port:
```

Открывает последовательный порт. `with` гарантирует, что порт будет закрыт при выходе из блока. `timeout=0.1` ограничивает ожидание данных чтением примерно 0.1 секунды. В документации pySerial `read(size)` описан как чтение до указанного количества байтов; при установленном тайм-ауте может вернуться меньше байтов.

После короткой паузы `reset_input_buffer()` очищает старые байты, чтобы не разобрать остаток предыдущего сеанса. Затем `write()` отправляет плате ASCII-команду `tm_start N` с символом возврата каретки `\r`, который ожидает протокол прошивки.

`deadline = time.monotonic() + seconds` задаёт абсолютный срок окончания сбора. `monotonic()` подходит для измерения интервалов: он не является календарными часами и не должен прыгать при синхронизации системного времени.

`port.read(256)` получает очередную порцию байтов. `.decode("ascii", "replace")` превращает байты в текст; режим `replace` не даёт неожиданному байту обрушить декодирование. Далее строка добавляется к `received`, из неё извлекаются завершённые строки, а `parse_record()` выбирает только телеметрию.

`try/except KeyboardInterrupt/finally` отвечает за безопасную остановку. Если пользователь нажмёт Ctrl+C, цикл будет прерван, но блок `finally` всё равно отправит `tm_stop`. Иначе плата могла бы продолжить передавать поток после завершения программы на ПК.

### 6.4. `save_csv(records, name)` — записать измерения

CSV — обычный текстовый формат таблицы. Первая строка содержит имена полей:

```text
time_s,voltage_v,temp_c
```

Значения переводятся в удобные единицы и формат:

- `time_s` — секунды от первой записи;
- `voltage_v` — вольты, три знака после точки;
- `temp_c` — градусы Цельсия, один знак после точки.

`newline=""` рекомендуется при записи через модуль `csv`, в частности для корректной обработки окончания строк в Windows. `csv.writer` сам формирует разделители и строки.

### 6.5. `load_csv(name)` — прочитать таблицу

`csv.DictReader` читает первую строку как имена столбцов. Поэтому можно обратиться к полю по имени: `row["time_s"]`, `row["voltage_v"]`, `row["temp_c"]`. Значения из текстового CSV преобразуются в `float` и попадают в три списка.

### 6.6. `plot(csv_name, png_name)` — построить график

`matplotlib.use("Agg")` выбирает графический backend без интерактивного окна. Это полезно на сервере автоматической проверки, где нет рабочего стола. `plt.subplots(2, 1, sharex=True)` создаёт два графика один под другим, с общей осью времени.

Верхний график показывает напряжение GP26, нижний — температуру кристалла. `grid(True)` включает сетку, `tight_layout()` подбирает отступы, `savefig()` записывает изображение PNG.

Обрати внимание: график строится из CSV, а не напрямую из списка `records`. Это разделяет две задачи: сначала сохраняем данные как самостоятельный результат, а затем визуализируем этот файл. Поэтому график можно построить повторно без платы.

### 6.7. `argparse` — параметры командной строки

Скрипт поддерживает три параметра:

```powershell
python get_telemetry.py
python get_telemetry.py --seconds 30 --period 50
python get_telemetry.py --plot telemetry.csv
```

- `--seconds` — сколько секунд принимать поток, по умолчанию 10;
- `--period` — период телеметрии платы в миллисекундах, по умолчанию 100;
- `--plot CSV` — только построить график из уже готового CSV, не искать плату.

Это два режима одной программы: сбор с прибора и офлайн-визуализация готового набора данных.

## 7. Почему стандартный запуск даёт около ста записей

При периоде 100 мс:

\[
 f_s=\frac{1}{0.1\text{ с}}=10\text{ отсчётов/с}.
\]

За 10 секунд ожидаем ориентировочно:

\[
 N\approx f_s T=10\cdot10=100\text{ записей}.
\]

Точное количество может отличаться на одну-две записи из-за момента старта и остановки. При периоде 50 мс частота составит 20 отсчётов/с, и за 10 секунд получится примерно 200 записей.

Для реальных сигналов частоту выбирают по скорости их изменения. Если пытаться измерять быстро меняющийся сигнал слишком редко, часть изменений будет пропущена или искажена (алиасинг). Для данной лабораторной мы наблюдаем сравнительно медленные параметры: плавающий вход и температуру кристалла.

## 8. Что проверить после запуска

1. Скрипт автоматически находит Pico.
2. В консоли появляются строки с временем, напряжением и температурой.
3. Создаётся `telemetry.csv` с точным заголовком `time_s,voltage_v,temp_c`.
4. Временные отметки начинаются с нуля и идут примерно с шагом 0.1 с при стандартном режиме.
5. Создаётся `telemetry.png` с двумя графиками.
6. Команда `python get_telemetry.py --plot telemetry.csv` строит график без подключённой платы.

## 9. Частые проблемы

- **«Плата не найдена».** Проверь кабель с линиями данных, прошивку п3.1.3 и появление Pico в диспетчере устройств. Скрипт ищет конкретные VID/PID `2E8A:000A`.
- **COM-порт занят.** Закрой PuTTY, Thonny, serial monitor или другой терминал, подключённый к Pico.
- **`ModuleNotFoundError: matplotlib`.** Запусти `python -m pip install -r requirements-telemetry.txt` тем же Python, которым запускаешь скрипт.
- **Не получено ни одной строки.** Убедись, что на плате именно прошивка п3.1.3 и она поддерживает `tm_start`/`tm_stop`.
- **CSV нет.** Он создаётся только если принято хотя бы одно корректное сообщение `tm:`.
- **Нужно только пересоздать PNG.** Используй режим `--plot`; плата не требуется.

## 10. Главная идея занятия

Плата выполняет измерение в физическом мире и присваивает ему собственную временную метку. Компьютер не пытается измерить сигнал повторно: он принимает готовые цифровые записи, правильно восстанавливает границы строк, сохраняет результаты в переносимом табличном формате и строит график.

Именно так устроен простой измерительный регистратор: датчик и АЦП → прошивка → интерфейс связи → программа сбора → файл данных → анализ и визуализация.
