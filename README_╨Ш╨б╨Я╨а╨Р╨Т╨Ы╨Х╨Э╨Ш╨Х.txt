Исправление ошибки линковки при включении профилирования (п2.3.8)

Скопируйте файлы из папки 231-firmware-template в существующий проект,
сохранив структуру папок, и файлы из папки libs в соседнюю папку libs.
Заменяйте только соответствующие файлы, не удаляйте .git и build вручную.

Причина ошибки:
main.c вызывал profiling_stopwatch_init(), этот символ был объявлен в
libs/profiling/include/profiling/profiling.h, но не имел реализации в
libs/profiling/src/profiling.c. Пока PROFILING_ENABLED=0, заголовок заменял
вызов пустым макросом; при включении профилирования стала видна ошибка линковки.

Исправления:
- добавлена реализация profiling_stopwatch_init() для фиксированных ID в main.c;
- таймеры используют systime_us() через библиотеку systime;
- profiling/CMakeLists.txt зависит от systime, а порядок подключения библиотек
  изменён так, чтобы systime был объявлен раньше profiling;
- profiling_get() возвращает все выделенные секундомеры, включая нулевые
  счётчики сразу после profiling_reset();
- команды help упорядочены так же, как ожидаемые группы в примере приёмки.

После копирования из корня проекта 231-firmware-template выполните:
cmake -S . -B build
cmake --build build --clean-first

Это не подтверждает приёмку само по себе: после сборки нужно заново записать
UF2 на плату и запустить python .\check-2-3-8.py.
